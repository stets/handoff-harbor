A working WordPress login is not a complete Kadence handoff.

The messy version: Kadence Pro is licensed to the freelancer, the client does not know which global colors drive the site, reusable blocks and hooked elements are undocumented, form notifications still point to a test inbox, and nobody owns updates or backups.

This is not legal, tax, hosting, security, accessibility, or Kadence/WordPress policy advice. It is a practical closeout checklist for freelancers and small studios so ownership, licenses, editing rules, support limits, and maintenance options are written down before final acceptance.

What to document before a Kadence project is accepted

Ownership, access, and licenses

Confirm WordPress admin ownership, hosting, registrar/DNS, SSL, recovery email, 2FA, Kadence Theme/Blocks Pro license owner, other premium plugins, renewals, and whether freelancer access remains.

Kadence design system

Record the global color palette, typography, buttons, spacing, header/footer builder, Customizer settings, Kadence templates or hooked elements, reusable blocks, and Starter Template changes.

Forms, integrations, and operations

Test forms, SMTP, recipients, spam protection, analytics, Search Console, pixels, caching, image optimization, backups, security, updates, redirects, and staging if used.

Editing and support boundary

Show safe page, post, image, and form edits; flag global palette, header/footer, template, block, plugin, and cache changes as higher risk; state the bug-fix window and paid-work route.

Copy/paste Kadence WordPress handoff checklist

  • ☐ WordPress admin owner, user roles, recovery email, 2FA, hosting, registrar, DNS, SSL, email provider, and renewal contacts are documented.
  • ☐ Kadence Theme/Blocks Pro license owner, key location, renewal responsibility, premium add-ons, child theme, custom code, and plugin dependencies are recorded.
  • ☐ Global palette, typography, buttons, spacing, breakpoints, header, footer, menus, Customizer settings, and sitewide defaults are summarized.
  • ☐ Kadence Blocks, reusable patterns, row layouts, templates, hooked elements, dynamic content, custom fields, and Starter Template modifications are explained.
  • ☐ Forms, SMTP, notifications, autoresponders, spam protection, CRM/newsletter connections, analytics, pixels, Search Console, and conversion events are tested.
  • ☐ Caching, CDN, image optimization, backups, security, staging, update workflow, uptime monitoring, and rollback process have a named owner.
  • ☐ Mobile, tablet, desktop, browser, link, redirect, 404, form, basic accessibility, and accepted known-issue checks are reviewed.
  • ☐ Client training distinguishes safe text/image/blog edits from risky global palette, header/footer, template, plugin, custom-code, and cache edits.
  • ☐ Included support has an end date; new pages, redesigns, SEO/copy, integrations, plugin work, performance work, troubleshooting, and maintenance route to paid work.
